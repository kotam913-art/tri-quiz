# 満点だけ提出する設定

## 2026-10-22 GitHub Pages対応版（受付 v4）

授業で配布するURLは https://kotam913-art.github.io/tri-quiz/ です。以前のHTML配信サービスを経由せずにクイズを開きます。

新URLからの自動提出を有効にするには、先生側の `Code.gs` をこのフォルダーの最新版へ置き換え、既存のウェブアプリを「新バージョン」で更新してください。`adminSetup` の再実行は不要です。更新前でも、満点後の「Googleの画面で提出する」から直接提出できます。

受付では新URLと従来のURLの両方を許可します。ほかの配信先を使う場合は、明示的に許可先を追加してください。

Googleログインを必須にしない運用では、実行ユーザー「自分」、アクセスできるユーザー「全員」でデプロイします。学校アカウントの管理設定で選べない場合は、許可されている設定を使います。スプレッドシート自体の共有範囲を変える必要はありません。

## 2026-10-20 送信トラブル対策版（受付 v3）

先生側は `Code.gs` の全体を最新版へ置き換えて保存し、同じデプロイを「新バージョン」で更新してください。名簿・提出コード・満点記録を作り直す必要はありません。`adminSetup` は集計列も更新したい場合に実行します。

- サイトで満点後に「Googleの画面で提出する」が使えます。これはGoogleの画面を直接開くため、教材の埋め込み内でログインできない端末の代替経路になります。学校のアクセス許可は引き続き必要です。
- 直接提出では学年・組・出席番号・提出コードを再入力します。回答は引き継がれますが、コードや生徒番号をリンクに含めません。
- Googleの画面で「提出済み」と表示されれば完了です。元の教材画面には完了が戻らないため、そこでの表示更新を待つ必要はありません。
- ログイン後に「回答が引き継がれていません」と出た場合、教材へ戻って直接提出リンクを押し直してください。満点を取り直す必要はありません。
- 全角英数字と前後の空白は照合時に整えます。英字の大文字・小文字は区別します。名簿のD列は表示文字列で照合します。数字だけのコードでは「書式 → 数字 → 書式なしテキスト」を推奨します。過去に消えた先頭の0は復元できないため、必要なら先生が再設定してください。
- 「名簿なし」「名簿の番号重複」「コード不一致」「課題未登録」「受付混雑」「接続待ち」「応答待ち」を区別して表示します。
- 多人数同時送信で保存が混み合った場合は、少し時間をずらして再送します。保存側の重複防止は維持します。

### 確認する設定

「デプロイを管理」で、実行ユーザーが先生の「自分」、アクセス範囲が学校の規則の範囲で生徒にも許可されていることを確認します。ログイン制限の解除や匿名公開をする必要はありません。学校側が利用を許可していない場合は管理者への確認が必要です。

更新後は、先生端末だけでなく送信できなかった生徒の端末で、満点未満は記録されない・正しい回答は保存できる・再送しても重複しない、の3点を確認してください。

対象は三角関数4教材と指数対数18教材です。満点未満は送信・保存しません。満点時の回答はサーバーで再採点した後に破棄し、学年・組・番号・課題・達成日時だけを記録します。

## 先生が最初に行う操作

1. 学校アカウントで空のGoogleスプレッドシートを作成。生徒には共有しません。
2. 「拡張機能 → Apps Script」を開き、Code.gsの内容を、このフォルダーのCode.gsで置き換えて保存します。
3. 上の関数一覧で `adminSetup` を選び「実行」。権限を確認して許可します。「名簿」「満点記録」「集計」の3シートが作られます。
4. 名簿に学年・組・出席番号を入力します（1人1行、氏名不要）。`adminIssueCodes` を実行すると、D列に生徒別の提出コードができます。それぞれの生徒へ本人分だけ配布してください。コードを知る人はその番号で提出できるため、名簿シート全体を生徒へ共有しないでください。
5. 「デプロイ → 新しいデプロイ → ウェブアプリ」。実行ユーザーは「自分」。アクセス範囲は学校で許可される設定を選びます。埋め込みで学校ログインが通らない場合は端末のブラウザーでログイン後に再試行してください。学校の制限を解除する必要はありません。制限で利用できない場合はドメイン内にホストする方式へ変更が必要です。
6. 発行された `/exec` で終わるウェブアプリURLを担当者（このチャット）へ送ってください。サイト側の `submission/config.js` に接続先として設定すれば有効になります。URLに生徒情報や秘密鍵は含まれません。

## 運用

- 1年度・1生徒・1教材につき1回だけ記録し、集計では1点とします。年度は4月始まりです。
- 集計シートは今年度の名簿全員を表示します。0は満点提出なしです。未挑戦と挑戦中は区別しません。
- 今回は4教材それぞれが1課題です。日ごとに同じ教材を別課題として加点する機能は含みません。
- 通信エラー時は「登録・再送」。保存成功の応答が返るまで「提出済み」と表示しません。
- 入力した番号は同じタブの間だけ保持し、提出コードはブラウザーへ保存しません。
- 満点になった回答を送って確認する方式です。練習教材の正答は元々ブラウザーに存在するため、試験用の不正防止機能ではありません。
- コードを修正した際は「デプロイを管理 → 編集 → 新バージョン」で更新します。

## 利用前の動作確認

テスト用の番号を名簿へ入れてコードを発行し、学校の生徒端末で確認します。
1. 間違えた提出で満点記録が増えない。
2. 各教材で満点にすると1行増え、集計に1点が入る。
3. 同じ満点結果を再送しても行・点が増えない。
4. 間違った提出コードで記録されない。
5. 通信を切ると「提出済み」にならず、復旧後に再送できる。

接続先が未設定の間は「準備中」と表示し、従来どおり練習できます。実際の学校アカウント・iPadでの接続は、デプロイ後に確認する必要があります。

## 指数・対数追加時の更新
コード全体を最新版に置き換えて保存し、adminSetupを実行します。その後「デプロイを管理」→編集→新バージョンで既存デプロイを更新してください。名簿・提出コード・満点記録は保持します。18課題はそれぞれ年度内1回、各1点です。
