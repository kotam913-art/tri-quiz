# 満点だけ提出する設定

対象はトップページの4教材です。満点未満は送信・保存しません。満点時の回答はサーバーで再採点した後に破棄し、学年・組・番号・課題・達成日時だけを記録します。

## 先生が最初に行う操作

1. 学校アカウントで空のGoogleスプレッドシートを作成。生徒には共有しません。
2. 「拡張機能 → Apps Script」を開き、Code.gsの内容を、このフォルダーのCode.gsで置き換えて保存します。
3. 上の関数一覧で `setup_` を選び「実行」。権限を確認して許可します。「名簿」「満点記録」「集計」の3シートが作られます。
4. 名簿に学年・組・出席番号を入力します（1人1行、氏名不要）。`issueCodes_` を実行すると、D列に生徒別の提出コードができます。それぞれの生徒へ本人分だけ配布してください。コードを知る人はその番号で提出できるため、名簿シート全体を生徒へ共有しないでください。
5. 「デプロイ → 新しいデプロイ → ウェブアプリ」。実行ユーザーは「自分」。アクセス範囲は学校で許可される設定を選びます。埋め込みで学校ログインが通らない場合は端末のブラウザーでログイン後に再試行してください。学校の制限を解除する必要はありません。制限で利用できない場合はドメイン内にホストする方式へ変更が必要です。
6. 発行された `/exec` で終わるウェブアプリURLを担当者（このチャット）へ送ってください。サイト側の `submission/config.js` に接続先として設定すれば有効になります。URLに生徒情報や秘密鍵は含まれません。

## 運用

- 1年度・1生徒・1教材につき1回だけ記録し、集計では1点とします。年度は4月始まりです。
- 集計シートは今年度の名簿全員を表示します。0は満点提出なしです。未挑戦と挑戦中は区別しません。
- 今回は4教材それぞれが1課題です。日ごとに同じ教材を別課題として加点する機能は含みません。
- 通信エラー時は「登録・再送」。保存成功の応答が返るまで「提出済み」と表示しません。
- 入力した番号は同じタブの間だけ保持し、提出コードはブラウザーへ保存しません。
- 満点になった回答を送って確認する方式です。練習教材の正答は元々ブラウザーに存在するため、試験用の不正防止機能ではありません。
- コードを修正した際は「デプロイを管理 → 編集 → 新バージョン」で更新します。

## 利用前の動作確認

テスト用の番号を名簿へ入れてコードを発行し、学校の生徒端末で確認します。
1. 間違えた提出で満点記録が増えない。
2. 各教材で満点にすると1行増え、集計に1点が入る。
3. 同じ満点結果を再送しても行・点が増えない。
4. 間違った提出コードで記録されない。
5. 通信を切ると「提出済み」にならず、復旧後に再送できる。

接続先が未設定の間は「準備中」と表示し、従来どおり練習できます。実際の学校アカウント・iPadでの接続は、デプロイ後に確認する必要があります。
