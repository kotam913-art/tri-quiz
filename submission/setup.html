スマホで403になる場合

生徒には https://kotam913-art.github.io/tri-quiz/ を配布してください。Classroomに貼った古いURLも差し替えます。クイズは外部のHTML配信サービスを経由せずに開きます。

新URLからの自動提出には、下の受付コードへの更新が一度必要です。更新前でも、満点後の「Googleの画面で提出する」から提出できます。

新URLからの自動提出を有効にする更新
  1. 下の「最新版コードをコピー」を押します。
  2. 集計用スプレッドシート →「拡張機能 → Apps Script」→「コード.gs」の内容全体を置き換えて保存します。
  3. 「デプロイ → デプロイを管理」→ 今使っているウェブアプリ → 鉛筆マーク → バージョン「新バージョン」→「デプロイ」。新しいデプロイは作りません。
  4. 実行ユーザーは先生の「自分」。Googleログインなしで使う場合、アクセスできるユーザーは「全員」にします。学校の管理設定で選べない場合は、学校で許可された設定を使います。集計用スプレッドシート自体は生徒へ共有しません。
  5. 生徒は新URLから教材画面を開き直します。自動で送れない場合は、満点後の「Googleの画面で提出する」で開き、学年・組・番号・コードを入力します。Googleのログイン画面が出る設定の場合は学校アカウントを使います。

今回は名簿・提出コード・満点記録を作り直す必要はありません。集計シートの更新も必要な場合だけ、エディタ上部で adminSetup を選んで実行します。

更新後の確認

送信できなかった生徒端末で、満点の提出が「満点記録」に入り、同じ課題を再送しても増えないことを確認してください。直接提出の完了はGoogleの別画面で表示されます。元の教材画面には完了が戻らないため、そちらの表示更新を待つ必要はありません。

ログイン後に「回答が引き継がれていません」と表示されたら、教材に戻って「Googleの画面で提出する」を押し直します。満点の取り直しは不要です。アクセス権のエラーが出る場合は学校の設定確認が必要です。

初めて設定する場合
  1. 学校アカウントで空のGoogleスプレッドシートを作成。生徒へ共有しません。
  2. 上のコードをApps Scriptへ貼り付けて保存し、adminSetupを実行します。名簿・満点記録・集計・単元別集計2枚の計5シートが作られます。
  3. 「名簿」へ学年・組・番号を入力してadminIssueCodesを実行。D列のコードは本人分だけ配布します。
  4. 「新しいデプロイ → ウェブアプリ」で、実行ユーザー「自分」、学校で許可されたアクセス範囲でデプロイします。
  5. 発行された/execのURLを担当者へ伝え、サイトの接続先を設定します。
